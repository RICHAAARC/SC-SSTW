## Forward-path repair after run04

The previous blanket save_on_cpu saved frozen resident weights alongside activations. The replacement uses saved_tensors_hooks and builds a set of storage identities from the current transformer/VAE parameters and buffers. Views sharing those storages stay on their original device. Only other saved tensors are moved to CPU and restored to their original device during backward; requires_grad=False is not used as the classification rule. No model offload, tensor deduplication cache, recomputation, dtype change or budget change is added. Normal prefix, OFF, candidate and final paths remain no_grad. Forecast terminal RGB/loss graph references are released after finite-gradient checks and before candidate rollout.

Top-level state becomes RUNNING before loading. counts.json contains attempted/completed counters and the most recent stage/time in one compact write per event. progress.json writes the in-memory event history once at worker completion/failure. START reserves a call; COMPLETE means its Python call returned successfully, not an explicit CUDA synchronization. Failed or interrupted calls remain attempted without completed. Model load, prefix, arms, differentiable forecast, backward, candidate, VAE and MP4 readback expose progress. No extra GPU synchronize or resource gate is added.

Linux parent-death signaling and an immediate parent-PID recheck cover launcher/worker parent loss. Cancellation first requests worker cleanup, then kills its process group after at most three seconds; a worker whose parent disappeared persists its outcome before terminating its group, including codec descendants. The notebook holds a Popen handle and propagates interruption, with a bounded fallback. There is no watchdog service. run04 is retained; the next local candidate notebook output is run05. This repair has not been pushed or run on real GPU weights.

Cancellation evidence is limited to responsive Linux Python processes and real dummy descendants. Python signal handlers may be delayed by a long native call; if the launcher is already killed, no live launcher remains to enforce the three-second escalation. No claim is made for arbitrary native hangs or whole-VM death. No watchdog service is added for that unverified case.
