# Local checkpoint proposal

This local engineering route replaces activation transfer with bounded recomputation. It has not run pretrained Wan weights or a GPU. The existing default GPU configuration/notebook is not silently changed; the separate proposal is `configs/public_luma_phase2_checkpoint_proposal.json`. CPU transfer is false, and selecting both checkpointing and CPU saved-tensor transfer is rejected. No publication or GPU execution is implied by these files.

Transformer uses its official enable_gradient_checkpointing entry with a nonreentrant checkpoint function. Only differentiable forecasts enter it; normal generation remains unchanged. Replay early stop is disabled to count complete replayed blocks explicitly. Model weights, mixed BF16/FP32 rules, and solver state semantics are unchanged.

The FP32 AutoencoderKLWan reports unsupported generic gradient checkpointing. Its adapter instead reuses the engineering construction in archive/SC-SSTW-Feasibility/src/sstw/flow_guidance_embedder.py::_checkpoint_wan_decoder_frames. No archive code is imported. A scoped decoder.forward wrapper flattens incoming causal cache tensors, reconstructs a fresh local cache/cursor for every forward/replay, returns all outgoing cache tensors explicitly, and checks cache layout/consumption across replay. None/Rep markers and first_chunk behavior are preserved. The ordinary forward reconstructs native cache slots; backward replay never mutates the VAE global cache. Native vae.decode continues to own post_quant_conv, temporal chunk scheduling, unpatchify, clamp and clear_cache. The wrapper is restored even on exceptions. Expected chunk count is the actual latent temporal length, not a fixed13. The present proposal excludes spatial tiling and multivideo batches.

Cache tensor connections are never detached. A gradient from later output frames therefore reaches earlier latent chunks through the same causal history. Each checkpoint retains its explicit boundary inputs; internal activations are recomputed during backward. Boundary cache tensors remain on GPU, so this does not promise a particular full-model peak or eliminate OOM.

The existing top-level budget remains124 Transformer forwards/7 VAE decode calls/2 backwards/3 MP4/147 frames. Additional budget is a separate ledger: at most180 Transformer block replays (6 differentiable Transformer calls×30 blocks for the intended architecture) and26 decoder frame replays (2 differentiable decodes×13latent chunks). Actual loaded architecture/config is recorded and budget exhaustion is fatal; no model-version gate substitutes for actual accounting. CPU tiny3latent/one-block tests require6 extra blocks and6 extra decoder chunks. These counts use distinct units and must not be added to top-level VAE or Transformer counters as if they were the same operation. Recompute forward/completed counts refer to successful Python return, with no GPU synchronize.

Internal block/chunk counters are memory-only. Existing compact top-level progress attaches their latest summary without extra per-block Drive writes; a hard kill between stages can leave that snapshot behind actual replay work. Worker cleanup writes final recomputation.json with counts, bounds and boundary-storage diagnostics. Each boundary reports logical tensor bytes and deduplicated backing-storage bytes. Per-decode phase union tracks storage identities, not live peak allocation (in particular replay allocator reuse affects that interpretation). The ledger retains only numeric records/identities, no tensors or storage objects. Independent saved-tensor storage probes are needed for memory conclusions.

CPU validation uses random real tiny AutoencoderKLWan and mixed-precision WanTransformer3DModel with real UniPC. Tests compare native vs checkpointed13latent→49RGB frames and latent gradients, cross-chunk cache derivatives, restoration, bounded replay failure, and full OFF1/OFF2/Y_MINUS flows with unchanged loss/quality acceptance. Old successful engineering is evidence for this adaptation, not evidence that the full remaining-solver scientific result or a pretrained GPU execution succeeds.
