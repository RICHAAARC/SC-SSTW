## Blind receiver

The selector receives only the decoded RGB video, the requested key, and the public 181-position clock protocol. It does not receive the attack label, attack parameters, payload bits, edit truth, or an arm-specific route. A frozen framewise VAE produces one latent per received frame. For each received frame and each public source position, the receiver records `signed_projection` and `rho` and scores their ratio. A nondecreasing dynamic program allows stay, advance-one, and arbitrary skip transitions with free start and end. It retains two distinct complete paths. An exact best-path tie is `UNRESOLVED`; no path is selected from payload evidence.

For a unique blind path, the visible span starts at `floor(s_min/4)*4`, requiring at most three front boundary copies. Missing source coordinates use the nearest received estimate; equal distance chooses the earlier received frame. The result is truncated to `1+4k`, and the receipt records source span, received map, synthetic outputs, repeats, dropped inputs, and tail discard. RAW uses the same received video but has no source-position estimate: its source-coordinate entries are null and its received-coordinate entries are explicit. Both modes use `R=min(44,T_latent-1)` and the existing FFT coordinates and Counter decision. Too little visible support is `UNSUPPORTED` with 32 missing bits.

The runner stores clock matrices and raw signed payload votes/zero masks as compressed NPZ. JSON retains array shape, coordinate order, bit/time counts, decoded bits, and receipts. The independent check compares selected sign counts with the existing payload reader's saved vote counts; it is not a decoded-field self-comparison. Path error is joined only after blind work is sealed. It reports first-frame offset, mean/max/min-support absolute distance and weighted absolute distance. For mixed-frame truth, support distance can be zero while weighted distance is positive because the truth itself has spread.
