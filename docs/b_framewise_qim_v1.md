# Framewise QIM V1 — local implementation, no physical run

The adopted route keeps DCT2 identity and its E41 reader, with CDC32 unchanged. It adds a finite 181-RGB-frame, frozen final-activation control and matched RGB luma DCT-QIM reader. All new files use `b_framewise_qim_v1`; no previous route is edited. Authoritative implementation specification and review evidence are in the project root `diagnostics/framewise-qim-candidate-audit-20261029/`.

The pure module owns GF64/BCH63/24, global j, two full replicas, five lanes, fixed centers, DCT scaling, received-frame soft evidence and geometry. The solver minimizes the RGB residual with convex constraints; its zero initialization and range(A^T) updates select the minimum-norm coefficient preimage. It reports approximate KKT convergence, numeric/resource unresolved or the narrow zero-response infeasibility certificate. Finite steps do not establish exact optimality or native feasibility.

The runtime derives effective sparse head kernels from actual FP32 weights, solves in CPU FP64, and replays the original FP32 causal head using cached post-nonlinearity features. Modified history is passed explicitly; no stale prehook cache is assumed fixed. The original native decoder is run once. Full baseline and changed preclip tensors, fixed targets, coefficients, arithmetic/budget residuals and raw observations are retained.

Future user-run command, from an editable source folder (no `.git` required):

```bash
python -m experiments.wan_state_clock.b_framewise_qim_v1_run \
  --source /path/to/B-Terminal-Three-Group-V1/fixed-four-new-v1 \
  --output /path/to/new-framewise-qim-output
```

The package is one source, two arms, full 181 frames, eight layer reads / 912240 time-code slots, and 16 E41 views / 2560 identity bit slots. Budgets: one D181, 46 baseline and 46 changed-head calls; K and K^T at most 4201 each; 16 E41; encode/probe/decode each two; DiT and training zero. Head kernels use up to 138 tile-batch convolutions per full operator application. A 7200-second/4000-iteration CPU solver cap and 16-GiB estimated live-array limit are fixed. FP32 captured feature files require at least 32 GiB of free space or the larger actual-channel estimate. This budget has not been benchmarked on the physical model.

An attempt is reserved before work. Started calls and fixed rows persist; a second invocation reads receipts only. Errors and interrupted/unstarted rows remain in all denominators. Raw q/d0/d1/soft/mask are saved and reread before replica fusion; truth opens only for later assessment. Replica fusion never crosses received frames. BCH candidates are uncalibrated and are not presence or source authentication. Identity phase diagnostics retain partial cells; only actual full canonical cells enter the common-complete comparison. No new time-to-CDC32 adapter, H137, S or tau is fabricated.

CPU tests use artificial inputs, tiny convex examples and fake backends. They establish engineering properties only. Native solvability, cost, clamp/RGB8/H264 survival, DCT2 identity preservation, blind synchronization, long videos and scientific success remain untested.
